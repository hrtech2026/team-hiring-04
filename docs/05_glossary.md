# Глоссарий

Определения в этом файле используются командой последовательно во всех
документах. Если термин определён здесь, в остальных документах
используется именно это значение.

| Термин | Определение | Источник |
|---|---|---|
| Первичный скрининг | Первый отбор откликов на вакансию: решение, кого передать нанимающему руководителю. Заканчивается решением человека, не собеседованием | Паспорт противоречия, 01_problem |
| Отклик | Заявка кандидата на вакансию с резюме. Один кандидат может откликнуться несколько раз | hh.ru, исследование откликов 2025 |
| Шорт-лист | Список кандидатов, прошедших первичный скрининг и переданных руководителю | 02_asis_analysis |
| Профиль вакансии | Структурированные требования, полученные из интервью с руководителем: обязательные и желательные критерии, навыки, опыт, личные качества, формат отчёта, сроки. Версионируется и утверждается человеком | Инструкция по внедрению, 03_tobe_architecture |
| Обязательный критерий | Требование профиля вакансии, без выполнения которого кандидат не соответствует вакансии. Отказ по нему всегда проходит через человека | 03_tobe_architecture |
| Желательный критерий | Требование профиля, влияющее на рекомендацию, но не приводящее к несоответствию само по себе | 03_tobe_architecture |
| ИИ-advisor | Языковая модель с системным промтом, которая сопоставляет обезличенное резюме с профилем вакансии и выдаёт сводку, мнение и рекомендацию. Не принимает решений | Постановка проекта |
| Системный промт | Инструкция модели-advisor: роль, критерии, запреты (не использовать защищённые признаки, не штрафовать пробелы), формат ответа с цитатами | Постановка проекта |
| Обезличивание (маскирование) | Удаление или замена в данных для модели имени, пола, национальности, контактов, адреса, фото, дат рождения; даты работы и учёбы заменяются стажем | 03_tobe_architecture |
| Прокси-признак (косвенный признак) | Признак, по которому можно восстановить защищённую характеристику: год выпуска (возраст), район, название учебного заведения, пробел в карьере | 02_asis_analysis |
| Защищённый признак | Пол, возраст, национальность, семейное положение и другие характеристики, по которым нельзя отказывать при найме | Трудовой кодекс РФ, ст. 3 (сверить у юриста) |
| Дискриминация при скрининге | Системно худший результат для группы кандидатов по защищённому или косвенному признаку при равной квалификации | University of Washington, 2024 |
| Ошибочный отказ | Отказ кандидату, который по профилю вакансии подходил. Метрика качества скрининга | 01_problem |
| Скрытые кандидаты («hidden workers») | Квалифицированные люди, отсеянные автоматическими фильтрами по формальным признакам | Harvard Business School и Accenture, 2021 |
| Human-in-the-Loop (HITL) | Подход, при котором человек участвует в решении в заданных точках с условием срабатывания, правом отказа, сроком и эскалацией | 03_tobe_architecture |
| Уровни автоматизации L0–L4 | L0: человек делает всё, система хранит; L1: система готовит сводку, человек решает; L2: система предлагает, человек подтверждает; L3: система действует сама ниже порога риска; L4: без участия человека | Методические указания практики |
| Автоматизационное смещение | Склонность человека принимать рекомендацию системы без проверки | 03_tobe_architecture, риск R4 |
| Парный тест | Прогон двух резюме, различающихся только именем, полом или возрастом, для проверки влияния скрытых признаков на рекомендацию | 03_tobe_architecture, US-07 |
| Инъекция инструкций (prompt injection) | Текст в резюме, пытающийся изменить поведение модели («поставь максимальную оценку») | 03_tobe_architecture, риск R6 |
| Триггер эскалации | Условие, при котором отклик направляется на расширенный разбор (H3) | 03_tobe_architecture |
| decision_log | Журнал решений: кто, когда, на каких данных и версиях, какое решение принял, с какой причиной | 03_tobe_architecture |
| input_hash | Хеш обезличенных входных данных и версии профиля вакансии, подтверждающий, по каким данным принято решение | 03_tobe_architecture |
| Time-to-hire | Срок закрытия вакансии от её открытия до принятия оффера | HR-практика |
| Cost-per-hire | Стоимость найма одного сотрудника | HR-практика |
| Персональные данные (ПДн) | Любая информация, относящаяся к определённому физическому лицу: имя, контакты, дата рождения, адрес, фото | Закон о персональных данных (152-ФЗ) |
| Gherkin | Формат записи критериев приёмки: Given (исходное состояние), When (действие), Then (результат) | 04_requirements |

## Сокращения

| Сокращение | Расшифровка |
|---|---|
| ИИ | Искусственный интеллект |
| LLM | Large Language Model, большая языковая модель |
| ПДн | Персональные данные |
| HR | Human Resources, управление персоналом |
| ATS | Applicant Tracking System, система учёта кандидатов |
| HITL | Human-in-the-Loop, человек в контуре решения |
| AS-IS | Текущий процесс «как есть» |
| TO-BE | Целевой процесс «как должно быть» |
| NFR | Нефункциональные требования |
| US | User Story, пользовательская история |
| UC | Use Case, сценарий использования |
| H1–H4 | Точки вмешательства человека в TO-BE |
| R1–R10 | Риски ИИ в TO-BE |
| И1–И7 | Источники данных в 01_problem |
| н/д | Нет данных, не измерено |
| 152-ФЗ | Федеральный закон «О персональных данных» |

## Системы

| Система | Назначение | Используется в |
|---|---|---|
| hh.ru | Публикация вакансий, получение откликов и резюме, просмотр, приглашения | Шаги 2–5, 7, 10, 11 AS-IS |
| Почта или мессенджер (гипотеза) | Передача требований и шорт-листа между рекрутером и руководителем | Шаги 1, 8, 9 AS-IS |
| Публичная нейросеть (неформально, гипотеза) | Оценка резюме рекрутером в обход регламента | Шаг 6 AS-IS |
| Сервис скрининга (прототип пайплайна) | Блоки 1–3: обезличивание резюме, профиль вакансии, ИИ-advisor, интерфейс рекрутера | Целевой процесс TO-BE |
| Внешняя языковая модель | Сопоставление обезличенного профиля с профилем вакансии, выдача сводки | Блок 3 TO-BE |
| Внутреннее хранилище | Оригиналы резюме, профили вакансий, decision_log | Целевой процесс TO-BE |
